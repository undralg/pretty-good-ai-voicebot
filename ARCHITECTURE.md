# Architecture

> **Status:** Implemented and exercised across live PSTN calls. Ten selected dual-channel MP3s and two-sided transcripts are packaged under `artifacts/final`; manual listening remains pending.

Twilio Programmable Voice places each outbound call from one consistent E.164 number to the assessment destination, which is an immutable code constant rather than CLI or environment input. Twilio receives inline TwiML containing `<Connect><ConversationRelay>`, then opens a signed WSS connection to FastAPI. ConversationRelay owns telephone audio, speech recognition, speech synthesis, turn detection, and caller barge-in. FastAPI validates Twilio signatures, loads one synthetic YAML scenario, tracks conversation history, and streams `gpt-4.1-mini` Responses API text deltas back as ConversationRelay `text` messages. A restricted Twilio API key is used for call creation and recording download; the account Auth Token is retained only for signed-callback validation.

The live loop treats generated text as provisional. `utteranceUntilInterrupt` is authoritative after barge-in, `tokensPlayed` is authoritative for completed patient turns, and the first replacement token preempts any stale queued talk cycle. Explicit goodbye/transfer phrases bypass the model, and a near-limit close sends a short farewell followed by ConversationRelay's `end` message; Twilio's 180-second call limit remains the final watchdog. Every call receives an immutable scenario snapshot, metadata, JSONL event log, rendered two-speaker transcript, and dual-channel MP3. Calls run sequentially so callbacks and artifacts remain unambiguous. The ten public candidates are copied from ignored private storage only after structural and audio-signal checks; human listening is deliberately a separate final gate.
